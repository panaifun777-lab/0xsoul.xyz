二、 第一部分：Solana 版 AI Agent 专用钱包方案（Agent Wallet & Swarm）
普通散户用币安 AI 钱包需要手机扫码，且单钱包受限于内盘 1% 的购买上限。我们设计的 Solana AI Agent 专用钱包系统 直接运行在独立容器内，兼具“对外发行给其他 AI 玩家使用”与“对内驱动你自己的 4 套迷因币量化系统”双重能力。
1. 钱包容器架构：主控金库 + 会话热签（Dual-Tier Container）
 * L1 主控身份层（Master Identity / Passkey Vault）：
   * 绑定用户的核心资产与 .web4 / .soul 主身份，私钥通过分片或硬件隔离保存，仅用于资金划拨与派发子钱包授权。
 * L2 执行代理层（Ephemeral Session Wallets / Ed25519 子钱包集群）：
   * 通过确定性派生（HD Path: m/44'/501'/agent_index'/0'）在 Docker 容器内存中批量生成专用 Agent 交易子钱包。
   * 每个子钱包在链上自动铸造一枚 Agent Identity PDA（不可转让的 Token-2022 Non-Transferable Mint），从而获得平台内盘的合法准入资格。
   * 突破 1% 限购：当你看准一个内盘标的时，调度器（Orchestrator）可通过 Jito Bundle 在同一个 Slot（400ms）内同时调用 5–10 个拥有独立 Agent ID 的子钱包并发买入，合规拿到 5%–10% 的早期筹码。
2. 硬编码策略风控引擎（Policy-Enforced Auto-Signer）
参考目前 Solana 生态最前沿的 Agent CLI 安全范式，权限控制绝不能写在 LLM 的 Prompt 里（防提示词注入），必须硬编码在钱包签名守护进程（Signer Daemon）中：
 * 默认锁死转出权限：canTransferExternal = false（只允许与白名单 Launchpad 合约、Raydium、Jupiter 交互，即使 AI 被注入攻击也无法将 SOL 转走）。
 * 单笔与日度熔断：限定单次内盘狙击上限（如 maxBuyPerTx = 1.5 SOL）、滑点上限（maxSlippageBps = 500）与每日最大亏损额。
 * 极速免确认模式（--auto-approve）：只要交易指令（Instruction）解码后符合上述沙盒规则，守护进程直接在内存完成 Ed25519 签名并通过 Jito / Helius 节点广播，耗时小于 15 毫秒。
3. 核心代码骨架：Solana Agent 专用钱包签名器（TypeScript）
import { Keypair, VersionedTransaction, PublicKey, Connection } from '@solana/web3.js';
import bs58 from 'bs58';
export interface AgentPolicyConfig {
  allowedProgramIds: Set<string>; // 仅允许内盘 Launchpad / Raydium / Jupiter Program ID
  maxSolPerTx: number;            // 单笔最大消耗 SOL
  canTransferOut: boolean;        // 严禁向未知外部地址转账
}
export class SolanaAgentWallet {
  private keypair: Keypair;
  private policy: AgentPolicyConfig;
  public readonly agentIdPda: PublicKey;
  constructor(secretKeyBase58: string, agentRegistryProgramId: PublicKey, policy: AgentPolicyConfig) {
    this.keypair = Keypair.fromSecretKey(bs58.decode(secretKeyBase58));
    this.policy = policy;
    // 派生该钱包在平台上的专属 Agent 身份 PDA (对应 gang.fun 的 .ai ID)
    [this.agentIdPda] = PublicKey.findProgramAddressSync(
      [Buffer.from('agent_passport'), this.keypair.publicKey.toBuffer()],
      agentRegistryProgramId
    );
  }
  public get publicKey(): PublicKey {
    return this.keypair.publicKey;
  }
  /**
   * 毫秒级策略沙盒校验与自动签名（取代人工手机扫码）
   */
  public async signIfPolicyAllows(tx: VersionedTransaction): Promise<VersionedTransaction> {
    const staticKeys = tx.message.staticAccountKeys;
    
    // 1. 校验调用的所有 Program ID 是否在白名单内
    for (const compiledIx of tx.message.compiledInstructions) {
      const programId = staticKeys[compiledIx.programIdIndex].toBase58();
      if (!this.policy.allowedProgramIds.has(programId)) {
        throw new Error(`[Policy Violation] 拦截未授权的合约调用: ${programId}`);
      }
    }
    // 2. 通过校验，直接在内存完成 Ed25519 极速签名
    tx.sign([this.keypair]);
    return tx;
  }
}
三、 第二部分：用我们的技术复刻 Solana 版 gang.fun 平台
在 Solana 上复刻 gang.fun，我们要打造一个 “Zero-UI（网页纯只读）+ 合约层强制 Agent 身份门禁 + 原生支持 AI 留言与自动分红” 的极客发射台。
1. 链上核心合约设计（Anchor / Rust 架构）
只需要部署两个核心 Program（或合并为一个核心 Program 的不同模块）：
① agent_passport（Agent 身份注册表模块）
 * 作用：复刻币安 .ai ID。任何 AI Agent 钱包只需支付极少量的费用（如 0.01 SOL 或通过 x402 支付 1 USDC），即可铸造一个与其公钥绑定的 AgentProfile PDA 账户。
 * 链上字段：记录 agent_handle（如 alpha.web4 或 sniper01.soul）、tokens_launched（发币数）、tokens_graduated（成功毕业数）、win_rate_bps（历史胜率）。
② agent_launchpad（内盘联合曲线与公平发射模块）
 * 合约级门禁（The Agent Gate）：
   * 在 create_token、buy_bonding_curve、subscribe_fair_mint 三个指令的 Context 约束中，强制要求传入调用者的 AgentProfile PDA 并验证 seeds 签名。没有注册 Agent 身份的普通 Phantom 散户钱包直接被合约层 ConstraintSeeds 拒绝交易。
 * 两种内盘发射模式：
   * Bonding Curve（联合曲线模式）：虚拟池初始设定（如虚拟 30 SOL + 10 亿枚代币），单个 Agent PDA 账户硬编码限购 1%（1000 万枚）。当真实募集满 85 SOL 时，触发 graduate_to_dex，合约自动抽取约 6 SOL 作为平台与创建者奖励，其余 ~79 SOL 与剩余 2 亿枚代币通过 CPI 自动注入 Raydium V4 或 Meteora 动态池，并永久销毁 LP Token。
   * Fair Mint（固定价格打新模式）：发币 Agent 设定募集上限（如 50 SOL）与单地址认购上限，满额后由任意 Agent 触发一键开盘；若超时未满，Agent 可调 refund 全额退回 SOL。
 * 原生交易笔记（On-Chain Agent Thought Stream）：
   * 复刻 gang.fun 的 --note 功能。买卖指令中包含 memo: String 参数（限制 140 字节），直接通过 Solana Event 日志抛出。前端看板可实时滚动展示各个 AI Agent 买入或砸盘的“思考推理过程”。
 * 外盘持币分红（Token-2022 Transfer Fee Extension）：
   * 利用 Solana 原生的 Token-2022 扩展标准，在创建代币时直接开启 TransferFeeConfig（如 1%–3% 交易税）。外盘交易产生的税费由守护进程定时归集，按比例自动空投给坚守持仓底线（未跌破 Hold Line）的早期 Agent 钱包。
Anchor 合约核心门禁伪代码示意：
#[derive(Accounts)]
pub struct BuyInternalPool<'info> {
    #[account(mut)]
    pub agent_signer: Signer<'info>,
    // 【核心门禁】强制校验调用者必须拥有合法的 Agent Passport PDA
    #[account(
        seeds = [b"agent_passport", agent_signer.key().as_ref()],
        bump = agent_passport.bump,
        constraint = !agent_passport.is_banned @ ErrorCode.AgentBanned
    )]
    pub agent_passport: Account<'info, AgentPassport>,
    #[account(mut)]
    pub bonding_curve: Account<'info, BondingCurveState>,
    
    // 记录该 Agent 在当前币种的持仓，强制执行单钱包 <= 1% 限购
    #[account(
        init_if_needed,
        payer = agent_signer,
        space = 8 + 64,
        seeds = [b"agent_position", bonding_curve.mint.as_ref(), agent_signer.key().as_ref()],
        bump
    )]
    pub agent_position: Account<'info, AgentPosition>,
    pub system_program: Program<'info, System>,
}
pub fn buy(ctx: Context<BuyInternalPool>, sol_amount: u64, min_tokens_out: u64, note: String) -> Result<()> {
    // 1. 计算联合曲线可获得的 Token 数量
    let tokens_out = ctx.accounts.bonding_curve.calculate_buy(sol_amount)?;
    require!(tokens_out >= min_tokens_out, ErrorCode.SlippageExceeded);
    // 2. 强制执行内盘单 Agent 1% 持仓上限 (例如总供应量的 1%)
    let new_balance = ctx.accounts.agent_position.amount_bought.checked_add(tokens_out).unwrap();
    require!(new_balance <= MAX_AGENT_HOLDING_CAP, ErrorCode.ExceedsOnePercentCap);
    // 3. 抛出带 AI 思考笔记的链上事件，供 Fastify 索引器毫秒级捕获
    emit!(AgentTradeEvent {
        agent: ctx.accounts.agent_signer.key(),
        agent_handle: ctx.accounts.agent_passport.handle.clone(),
        mint: ctx.accounts.bonding_curve.mint,
        is_buy: true,
        sol_amount,
        token_amount: tokens_out,
        thought_note: note,
    });
    Ok(())
}

五、 全局架构整合总结与演进蓝图
我们按照图片中的开发节奏，完成了一套面向未来的 Solana 极客发射平台：
钱包端（突破限购 + 全自动签名）：由 SolanaAgentClusterManager 调度派生的 Ed25519 容器化钱包群，结合硬编码的安全沙盒机制（validateAndSignTx），并打包到 Jito Bundle，避免被中间人夹子（MEV）截杀，抢占了多子钱包 1% 限购的打新早期筹码。
合约端（门禁隔离 + 原生 AI 留言）：Anchor 程序 gang_fun_solana 通过检验 AgentPassport 门票强制杜绝人工或爬虫直接登录，将 AI 交易理由 --note 写入交易元数据，并在募集到 85 SOL 时自动跨合约（CPI）打满流动性池并毕业。
网关与监听端（AI 一键托管 + zero-UI，对标 gang.fun）：Fastify 网关配合 IPFS Kubo 实现本地高效资源发布，通过提供 llms.txt 和 /api/tx/build 极简接口免去本地计算，多微服务由 docker-compose 一站式全隔离部署。
统一跨链前置：这套 TypeScript / Anchor(Rust) 微服务架构已在接口与指令（SDK）层实现了对 Chain ID 的解耦设计。当后期需要向 EVM（Base/BSC/ARC）迁徙时，底层智能合约换成对应的 Solidity 等效实现，Fastify 路由保持不变，量化套利模型和 AI 机器人一枪即可同时多链打狗。
对之前三阶段的集成代码进行严格的生产级复盘：核心骨架（钱包集群框架、买盘联合曲线、Agent Passport 门禁、Fastify 网关与 /llms.txt）已经对齐了约 65%，但距离 100% 复刻并超越 gang.fun 的完整生产闭环，还有 5 个关键模块在上一轮代码中被简化或尚未展开。

二、 分布式域名系统策略：用什么域名好？先内测还是直接上？
在这个系统中，“域名”实际上分为两层：第一层是链上 AI Agent 的专属身份后缀（对标币安的 .ai ID），第二层是交易平台本身的外部访问主域名（对标 gang.fun）。
核心结论：强烈建议“先用轻量级方案跑通内测闭环，待你的 4 套量化系统在实盘/测试网压测通过后，再通过跨链签名网关一键接入你的分布式域名体系”。
1. 第一层：链上 Agent 身份后缀怎么选？（.soul vs .web4）
你现有的分布式域名系统已经支持 .web4、.web5 和 .soul 后缀：
 * 最佳后缀推荐：首选 .soul（代表 AI Agent 的链上灵魂绑定凭证 Soulbound Identity，与不可转让的 Agent ID 概念完美契合），次选 .web4（代表机器与机器交互的 Web4 原生代理）。
 * 如何解决“现有域名在 EVM/ARC 链，而新平台在 Solana 链”的冲突？
   * 不需要在 Solana 上重写一套沉重的域名解析系统，更不需要做复杂的跨链桥。
   * 第 1 阶段（内测期）：直接在我们上一轮编写的 Solana AgentPassport PDA 账户里存入字符串（如 sniper01.soul），仅靠 Solana 单链 PDA 即可在 1 天内跑通内测。
   * 第 2 阶段（正式上线期 — 跨链签名映射）：采用 Fastify 网关预言机签名（Ed25519 Attestation）。当一个 AI Agent 在你的分布式域名系统上注册了 alpha.soul 后，你的 Fastify 网关验证其所有权并签发一张免 Gas 凭证，该 Agent 即可在 Solana 链上免费激活同名的 alpha.soul 交易通行证。这样既保护了你原有分布式域名系统的唯一权威性，又把 Solana 的高频交易流量全部导流回你的域名生态。
2. 第二层：平台主入口域名怎么选？（对标 gang.fun）
 * 内测阶段（零成本隔离启动）：
   * 严格遵循独立项目物理服务器隔离的原则，在独立的测试 VPS 实例上启动 Docker 容器，直接挂载一个现有测试域名的二级子域名（或临时测试域名）即可。因为 AI Agent 只认 /llms.txt 和 /api/market 的 URL，内测期完全不需要采购昂贵的新域名。
 * 正式公测阶段（面向全球 Agent 推广）：
   * Web2 镜像入口：采购一个极短的双音节 .fun、.sh（极客命令行属性极强，非常适合 CLI 驱动的平台）或 .ai 域名作为公网入口。
   * Web4 原生入口：同步在你现有的分布式域名网关上解析一个主域名（例如 gang.web4 或 meme.soul），实现传统互联网与去中心化网关的双轨访问。

/**
 * 标准 Solana BIP44 派生（与 Phantom / Solflare 完全兼容）
 */
export function deriveStandardSolanaKeypair(mnemonic: string, index: number): Keypair {
  const seed = bip39.mnemonicToSeedSync(mnemonic);
  const path = `m/44'/501'/${index}'/0'`;
  const derivedSeed = derivePath(path, seed.toString('hex')).key;
  return Keypair.fromSeed(derivedSeed);
}
/**
 * 构造 Jito Bundle 专用的末尾小费交易（确保 Bundle 被验证者优先打包）
 */
export function buildJitoTipTransaction(
  payerKeypair: Keypair,
  recentBlockhash: string,
  tipLamports: number = 100_000 // 默认 0.0001 SOL
): VersionedTransaction {
  const randomTipAccount = new PublicKey(
    JITO_TIP_ACCOUNTS[Math.floor(Math.random() * JITO_TIP_ACCOUNTS.length)]
  );
  const tipIx = SystemProgram.transfer({
    fromPubkey: payerKeypair.publicKey,
    toPubkey: randomTipAccount,
    lamports: tipLamports,
  });
  const messageV0 = new TransactionMessage({
    payerKey: payerKeypair.publicKey,
    recentBlockhash,
    instructions: [tipIx],
  }).compileToV0Message();
  const tx = new VersionedTransaction(messageV0);
  tx.sign([payerKeypair]);
  return tx;
}
2. 补齐 lib.rs 中的 AI Agent 内盘卖出指令（sell_bonding_curve）
    // 4. AI Agent 专用内盘卖出（联合曲线反向计算 + 持仓扣减 + 抛出砸盘理由 --note）
    pub fn sell_bonding_curve(
        ctx: Context<BuyBondingCurve>, // 复用相同的账户约束结构
        token_amount: u64,
        min_sol_out: u64,
        note: String,
    ) -> Result<()> {
        let passport = &ctx.accounts.agent_passport;
        require!(!passport.is_banned, ErrorCode::AgentBanned);
        let state = &mut ctx.accounts.bonding_curve;
        require!(!state.is_graduated, ErrorCode::TokenAlreadyGraduated);
        // 1. 计算联合曲线可换回的 SOL 数量: delta_sol = (pool_sol_balance * token_amount) / (pool_token_balance + token_amount)
        let numerator = (state.pool_sol_balance as u128)
            .checked_mul(token_amount as u128)
            .unwrap();
        let denominator = (state.pool_token_balance as u128)
            .checked_add(token_amount as u128)
            .unwrap();
        let gross_sol_out = (numerator / denominator) as u64;
        // 扣除 1% 平台内盘手续费 (100 bps)
        let fee_sol = gross_sol_out / 100;
        let net_sol_out = gross_sol_out.checked_sub(fee_sol).unwrap();
        require!(net_sol_out >= min_sol_out, ErrorCode::SlippageExceeded);
        // 2. 更新内盘池状态与 Agent 持仓记录
        state.pool_token_balance = state.pool_token_balance.checked_add(token_amount).unwrap();
        state.pool_sol_balance = state.pool_sol_balance.checked_sub(gross_sol_out).unwrap();
        state.total_raised = state.total_raised.saturating_sub(gross_sol_out);
        let current_position = &mut ctx.accounts.agent_position;
        current_position.amount_held = current_position.amount_held.saturating_sub(token_amount);
        // 3. 将 Agent 的 Token 转回内盘金库 ATA
        let cpi_ctx = CpiContext::new(
            ctx.accounts.token_program.to_account_info(),
            Transfer {
                from: ctx.accounts.agent_ata.to_account_info(),
                to: ctx.accounts.bonding_curve_ata.to_account_info(),
                authority: ctx.accounts.signer.to_account_info(),
            },
        );
        token::transfer(cpi_ctx, token_amount)?;
        // 4. 从 BondingCurve PDA 金库向 Agent 划转净额 SOL
        **state.to_account_info().try_borrow_mut_lamports()? -= net_sol_out;
        **ctx.accounts.signer.to_account_info().try_borrow_mut_lamports()? += net_sol_out;
        // 5. 抛出卖出事件与 AI 思考日志
        emit!(AgentTrade {
            agent: ctx.accounts.signer.key(),
            handle: passport.handle.clone(),
            mint: state.mint,
            is_buy: false,
            sol_amount: net_sol_out,
            token_amount,
            note,
        });
        Ok(())
    }

二、 结合草稿分析：还需进一步完善和植入的 5 大盲点
对照这份详尽的 v0.1/v0.2 草稿，系统在真正进入 Proof 0 之前，以下 5 个维度的细节需要进一步在架构和代码中植入：
1. 明确定义并植入 6 只 Agent 的角色分工（草稿第 4 节）
草稿提及了 6 只 Agent（Cyclops / Degen / Pincher / Razgon / Sniffer / Surfer），但未明确每只 Agent 的具体权限映射。建议在网关层植入基于 Agent 身份标签的 RBAC（基于角色的访问控制）：
Sniffer（嗅探者）：只读 + Veto（一票否决权）。配置 canSignTx = false。它只负责抓取链上新池、分析合约安全，若发现蜜罐或貔貅盘，直接向网关发送 POST /api/veto 将该 Token 压入黑名单。
Surfer / Degen（冲土狗主力）：canSignTx = true，但受到“单笔上限 + 日累计上限 + Turnkey 程序白名单”的严格约束。
Cyclops / Pincher / Razgon：可分别指派为不同策略（如突破追高、均值回归、聪明钱跟单），各自绑定不同的 Turnkey 子 Key 与独立每日限额池。
2. 补齐 Proof 0 的“支出限额是否覆盖 Swap”硬核边界测试（草稿第 5/8 节）
草稿明确指出：“支出限额是否覆盖 swap 是本方案最大的未验证点”。在开始 Proof 0 时，必须编写一段专项测试脚本（如 test-squads-limit.ts），在 Devnet 上实测：
当通过 Squads v4 的 AddSpendingLimit 授权给交易钱包一定数量的 USDC/SOL 后，尝试直接发起一笔 Jupiter CPI Call。
如果链上直接报错（证明 Squads v4 支出限额仅支持原生 SystemTransfer / SPL Transfer，不支持复杂的 CPI 组合指令）：则必须严格执行“A+B混合方案”中的资金补充流——即金库只能定期向交易钱包转账补充弹药，而不能由 Agent 直接用限额在金库里 Swap。
3. Turnkey 缺少“累计时间窗口限额”的网关补救植入（草稿第 5 节）
草稿提到 Turnkey 本身没有内置的“日累计限额（Daily Cumulative Limit）”管控。因此，Fastify 网关必须在内存/Redis 中强制植入 Redis 原子计数器：
每次 Agent 发起 POST /api/tx/build 时，网关必须先执行 Redis Lua 脚本： \text{CurrentDailySpent} + \text{RequestedAmount} \le \text{DailyLimit} 
只有当 Redis 计数校验通过后，才允许向 Turnkey 发送 SIGN_TRANSACTION 请求。如果 Redis 服务宕机或发生脑裂，网关默认执行安全失效（Fail-Closed），拒绝所有交易签名。
4. 黑名单（Blacklist / Veto List）的生命周期与动态刷新机制（草稿第 6 节）
草稿提到“黑名单 v1 已于 2026-10-31 前后过期”。如果 Agent 接入了一个过期的黑名单，等于形同虚设。
植入建议：网关必须建立一个自动同步守护进程（Cron / Worker），每隔 10 分钟从可信安全源（如 GoPlus API、Solana 知名防诈骗黑名单库、或你的 Sniffer Agent 动态共识库）拉最新黑名单，并动态写入网关内存的 Bloom Filter 中，确保黑名单拦截率始终为 100%。
5. x402 生产级微支付结算的接入时机（草稿第 6 节）
草稿中提到 x402 成本计入 PnL。在进入主网前，建议在网关中植入一个 x402 拦截中间件（HTTP 402 Payment Required）：
当外部 Agent 或非授权客户端调用你的高级情报接口（如聪明钱实时异动流 /api/market/alpha）时，网关自动返回 402 Payment Required 并附带 USDC 支付网关地址（Base 或 Solana USDC）。
待 facilitator 验证链上收到微支付后，向该 Agent 颁发带签名的短效 JWT 凭证，实现机器间的无感鉴权与自动打平 PnL。

📊 终极系统总结与商业闭环报告
一、 核心系统功能总结
本套系统专为机器对机器（M2M）的 autonomous AI Agents 打造，彻底剔除了传统人类浏览器的繁琐交互，构建了一个从“资金安全隔离、链上准入、极速打新到网关分发”的完整闭环：
多重安全与托管隔离架构（A+B 混合方案）：
储蓄层：基于 Squads v4 多签金库，私钥与 Agent 彻底隔离，通过受限支出限额向交易钱包定期补给弹药。
执行层：每只 Agent 拥有由 Turnkey 管理的独立 HSM 受限子钱包，私钥绝不落地服务端，且严格受限于网关白名单。
风控防线：Fastify 网关内置双重策略校验（Redis 日累计额度原子拦截 + 程序白名单 + 动态黑名单 Veto 机制），杜绝提示词注入带来的资产归零风险。
链上智能合约与身份门禁（Anchor / Rust）：
Agent Passport 门禁：通过 .soul / .web4（对应 Solana PDA 身份）将所有违规散户和普通脚本在合约层直接拦截，仅允许合法的 AI 身份参与内盘。
联合曲线与公平打新：支持满额自动触发跨合约（CPI）注入 Meteora / Raydium 迁移，并强制执行单 Agent 1% 持仓保护上限，防范科学家与巨鲸恶意砸盘。
链上思考流（--note）：每笔交易强制附加 140 字节的 AI 认知理由，形成链上可审计、可追溯的交易意图日志。
极客级 AI 接入与零 UI 看板：
标准机器可读协议：内置 /llms.txt 和 /api/tx/build，让 Claude、Cursor、Grok 或独立 Agent 框架无需本地推导复杂的 PDA 账户，直接获取序列化交易。
Zero-UI 极客大屏：通过 SSE（Server-Sent Events）毫秒级同步链上 Agent 交易流与内盘毕业进度，持续吸引大模型爬虫与开发者流量。
二、 商业效果与降维打击优势
降维打击传统 Meme 平台（如 Pump.fun）：
传统平台正在被“AI Agent 专属内盘”快速替代。本系统通过合约级身份门禁与免人工秒级交互，直接切入了未来占全网 Meme 交易额绝大部分的 M2M（机器交易机器）蓝海市场。
零前端攻击面与极低的运营成本：
平台不设传统前端钱包连接组件（No Connect Wallet），彻底规避了前端钓鱼网站、恶意授权（Drainer）和 DDoS 风险，研发与运维成本极低。
多元化的商业变现矩阵（x402 微支付 + 平台税）：
内盘手续费：通过内盘联合曲线与外盘 Token-2022 交易税分红抽成获取平台底层流水。
API 数据变现：利用 x402 协议对高级“聪明钱情报流”向外来的 AI Agent 收取 USDC 微支付门票，实现自动化的流量与数据变现。
