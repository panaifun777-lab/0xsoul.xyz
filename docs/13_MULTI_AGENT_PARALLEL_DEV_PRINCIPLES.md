# 0x.SOUL 多线程并行多智能体协同开发原则与标准规范

> **适用范围**：0x.SOUL 全生命周期软件工程、代码编写、安全审计与持续集成  
> **核心目标**：最大化多智能体并发开发效率，根除竞态条件与状态漂移，确保系统级确定性与高可靠性

---

## 1. 核心指导思想：无共享架构与清晰所有权

在多智能体并发协作（Multi-Agent Parallel Development）的工程环境中，代码冲突与状态混乱通常源于模糊的模块权责划分。本工程遵循以下四大元原则：

### 1.1 单一智能体代码所有权（Single Agent Code Ownership, SACO）
* 每一个子模块、代码文件或目录，在任何给定的研发周期内，**必须且仅能由一个特定角色的智能体拥有唯一的修改写权限**。
* 其他协同智能体需要该模块支持时，只能通过已锁定的接口定义（IDL / TypeScript Interface / OpenAPI Schema）进行调用或通过“请求合并（Pull Request / Patch Review）”模式交互，严禁跨模块强行覆写非自身权属范围的代码。

### 1.2 契约优先与接口冻结原则（Contract-First & Freeze Protocol）
* 在任何多智能体并行编码开始前，**首先由架构师智能体冻结模块间的数据契约**：
  * Solana Anchor 程序的 `IDL`（接口描述语言）与账户 PDA 数据结构。
  * Fastify 网关的 HTTP 路由、JSON Schema 与 WebSocket 消息格式。
  * 钱包沙盒的 `AgentPolicyConfig` 数据接口。
* 一旦契约评审通过并被打上基准版本号，所有研发智能体以此为不可变参照物进行独立并行编码，杜绝因为接口反复横跳带来的并发返工。

### 1.3 状态机无锁并发与消息总线驱动（Lock-Free Event Sourcing）
* 各研发智能体之间状态同步严禁依赖全局锁或内存共享，统一通过**结构化事件总线与工作流状态机**进行解耦通信：
  * 编译事件、测试报告、PR 审核意见统一以标准化 Markdown/JSON 格式落地留存。
  * 智能体通过轮询或事件订阅获取上游依赖产物，无依赖的任务立即并行执行。

### 1.4 安全红线与确定性验证准则（Proof-Before-Merge & Zero-Leak）
* **Proof 0 门禁制**：在没有通过 Devnet 安全边界与拦截实测（`proof0-validator.ts`）之前，严禁任何智能体编写涉及主网实盘资金的交易指令。
* **思想钢印与安全红线**：严禁在代码、注释、测试数据或提交日志中硬编码任何 API Key、私钥或助记词，一律使用容器环境变量注入；敏感令牌使用后立即从内存与配置中安全擦除。

## 3. 并发冲突预防与处理协议 (Anti-Collision Protocol)

1. **分支与工作区隔离**：
   * 每个研发智能体在独立的轻量分支或专用子目录下工作（如 `feature/solana-anchor-m2`、`feature/wallet-jito-m1`）。
   * 严禁多个智能体直接在主分支（`main` / `master`）上直接并发推送。
2. **三方比对与原子合入（Atomic Merge Gate）**：
   * 合并代码时，由 `AGENT-SEC` 执行自动化质量门禁（Quality Gate）：
     * 静态类型检查：`tsc --noEmit` 0 报错。
     * Rust 代码检查：`cargo check && cargo clippy -- -D warnings` 0 告警。
     * 单元测试覆盖率 $\ge 85\%$。
3. **死锁预防机制（Deadlock Prevention）**：
   * 若智能体 A 等待智能体 B 的产物超过预设超时时间（如 10 分钟），调度引擎自动根据已冻结的 Mock Interface 生成临时存根（Mock Stub），允许智能体 A 继续向下推进，防止单点阻塞引发整条研发流水线瘫痪。
